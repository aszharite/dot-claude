# Roadmap: <Product/Team Name>

## Now
What's actively being built this cycle.

- Keep this short — a handful of items, not everything in flight. If it's not something you'd say out loud when someone asks "what are you working on," it doesn't belong here.
- Link to the PRD or tracking issue for each item so "actively being built" is verifiable, not just asserted.

## Next
What's committed for the upcoming cycle(s), not yet started.

- "Committed" means resourced and prioritized, not just desired — if it could still get bumped by a reprioritization, it's Later, not Next.
- Order matters here more than in Later: this is roughly the sequence work will start in.

## Later
Directionally likely, not yet committed — sequencing/scope may change.

- Resist over-specifying — Later items should read as directions, not fully-scoped commitments; if you're writing acceptance criteria for one, it's not Later anymore.
- Revisit this list every cycle; items that go stale here for too long either need to move to Next or move to Explicitly not planned.

## Explicitly not planned
Things people keep asking about that are deliberately out of scope, and why.

- Only add things people actually keep asking about — this section is for closing recurring questions, not a general catalog of not-doing.
- State the "why," not just the "no" — a reason people can evaluate is what stops the question from resurfacing every quarter.

## Changelog
| Date | Change |
|---|---|

- Log every time an item moves between Now/Next/Later or gets added/dropped — the changelog is what lets someone reconstruct how the plan shifted without re-reading old versions of this doc.
- One line per change is enough; link to the decision-log or a discussion thread if the "why" needs more room.
