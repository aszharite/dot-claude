# PR/FAQ: <Product/Feature Name>

*Write the press release and FAQ before building, to force clarity on customer value.*

## Press release
Write it as if announcing the shipped product to customers today: headline, problem, solution, a representative customer quote, how to get started.

- Write it in the voice and length of a real press release (one page), not a spec — if it reads like a PRD, it's not doing its job of forcing customer-facing clarity.
- The customer quote should sound like a real person describing a real benefit, not marketing copy — if you can't imagine a real customer saying it, the value prop probably isn't sharp enough yet.
- *If you struggle to write the headline, that's a signal the core value proposition isn't clear yet — don't paper over it, fix the idea.*

## FAQ — customer questions
Anticipated questions a customer would ask, answered honestly (including "why would I want this").

- Include the skeptical questions, not just the easy ones — "why not just use [existing solution]," "what does this cost," "why should I trust this."
- Answer "why would I want this" as if to someone mildly annoyed by the pitch — if the honest answer is weak, that's real signal, not a writing problem.

## FAQ — internal questions
Anticipated questions from internal stakeholders: cost, timeline, risks, dependencies, what happens if we don't build this.

- Include the questions leadership will actually ask in the review, not softened versions of them.
- "What happens if we don't build this" deserves a real answer — if it's honestly "not much," that's important information before committing resources.
## Decision
Green-light to a full PRD, park, or drop.

- Make this a decision with an owner and date, not a lean — "green-light" should name who's writing the PRD next and by when.
- If the decision is "park" or "drop," capture why, so the same idea doesn't get re-pitched from scratch without that context.
