# OKRs: <Team/Product Name> — <Period>

## Objective 1: <Objective>
| Key result | Target | Current | Status |
|---|---|---|---|

- The objective itself should be qualitative and ambitious — a direction worth pursuing, not a number; the numbers live in the key results below it.
- Each key result must be a measurable outcome, not a task — "increase activation rate to 40%" is a key result; "ship onboarding redesign" is a project that might produce one.
- "Current" needs updating regularly for this table to mean anything — a stale "Current" column is worse than an empty one, since it looks live when it isn't.
- Status should reflect trajectory (on track / at risk / off track), not just distance from target — two key results at 50% can have very different statuses depending on time remaining.

| Key result | Target | Current | Status |
|---|---|---|---|

- Same discipline as Objective 1 — resist the temptation to make this one softer or less measurable just because it's second.
- If this objective doesn't need its own key results distinct from Objective 1, consider whether it's really a separate objective.

## Alignment
How these objectives ladder up to company/org-level goals.

- Name the specific company/org goal each objective supports — "supports growth" is too vague to check against later.
- If an objective doesn't ladder up to anything above it, that's worth flagging now, not discovering at review time.

## Retro
Filled in at period end: what was achieved, what wasn't, and why.

- Score each key result honestly against its target, not against effort expended — "we tried hard" isn't the same as "we hit it."
- Capture the "why" for misses specifically enough to inform next period's targets — "market conditions" explains less than "the assumption behind this target was wrong because X."
